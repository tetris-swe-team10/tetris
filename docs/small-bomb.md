- 담당: 정혜원

## 사용자 시나리오

아이템 모드에서 누적 10줄을 삭제하면 새로 보충되는 NEXT에 작은 폭탄을 예고한다.
사용자는 `E`가 붙은 칸을 보고 이동·회전하여 목표 위치에 놓는다.
고정 시 해당 칸 중심 3×3 안에서 지워질 블록이 0.3초 동안 흰색으로 두 번 깜빡인 뒤 제거된다.
위의 고정 블록은 떠 있는 상태로 남는다.

## 기능 명세와 경계 조건

| 항목 | 규칙 |
| --- | --- |
| 형태·문자 | 일반 테트로미노의 실제 점유 칸 중 무작위 한 칸에 `E` 부착 |
| 등장 | 아이템 모드 누적 10·20·30…줄 경계 통과 시 새 NEXT에 지급. 일반 모드에는 지급하지 않음 |
| 지급 시점 | 현재 표시된 NEXT는 바꾸지 않고, 다음 블록을 승격한 뒤 새로 생성하는 NEXT에 부착 |
| 초과 줄 | 9→13은 1회 지급, 누적 13 유지. 다음 경계는 20 |
| 예고 유지 | NEXT에서 본 아이템 종류·부착 위치가 현재 블록으로 승격될 때 유지됨 |
| 이동·회전 | 블록과 함께 이동·회전. 벽·다른 블록 때문에 회전 실패하면 아이템 좌표도 원상복구 |
| 발동 | 고정 직후 ITEM_EFFECT 진입 → 300ms 깜빡임 → 효과 1회. 자동·소프트·하드 드롭 모두 동일 |
| 연출 | 실제 제거될 점유 칸만 강조. 0~74ms 밝음 / 75~149ms 원래 색 / 150~224ms 밝음 / 225~299ms 원래 색 / 300ms 제거 |
| 연출 중 동작 | 고정된 보드·NEXT 유지, 현재 블록 중복 그리기 방지, 이동·회전·드롭·다음 블록 생성 차단 |
| 범위 | 최종 `E` 칸의 행·열 각각 ±1. 보드 밖 영역 무시. 방금 고정한 블록도 범위 안이면 제거 |
| 물리 | 폭발 자체의 중력·행 압축 없음. 범위 밖 칸의 위치·종류는 그대로 유지 |
| 연쇄 | 현재 고정된 블록의 효과만 실행. 제거한 칸을 원인으로 다른 아이템 호출하지 않음 |
| 점수·줄 수 | 폭발로 제거한 개별 칸은 추가 점수·누적 삭제 줄·속도 증가·아이템 지급에 포함하지 않음 |
| 일반 줄 삭제 | 폭발을 먼저 적용한 뒤 남아 있는 완성 행만 기존 300ms 연출·압축·점수·속도 규칙으로 처리 |
| 일시정지 | ITEM_EFFECT와 CLEARING 모두 시간·깜빡임 단계를 멈추고 재개 시 남은 시간부터 진행. 설정 화면 진입도 동일 |
| 게임 오버 | 확정 후 입력은 효과를 발동하지 않음. 폭발 직후 다음 블록을 놓을 수 없으면 기존 게임 오버 규칙 적용 |
| 재시작 | 새 엔진을 생성하므로 누적 줄·지급 예약·블록의 아이템이 초기화됨 |
| 식별 | NEXT와 현재 칸에 대비가 높은 `E` 배지. NEXT 아래 효과 설명. 색맹 모드에서도 문자 유지 |

NEXT 안내: **E 작은 폭탄 · 고정 후 주변 3×3 삭제**

## 구현 구조와 팀원 연동

- `GameItem`: 문자·설명·효과(`onLock`)와 선택적인 연출 범위(`previewCells`)·시간(`effectDurationMs`) 계약. 기본 범위는 빈 목록, 기본 시간은 0ms여서 기존 아이템은 즉시 실행된다.
- `SmallBomb`: 보드의 범위 안 칸만 `setCell(..., 0)`으로 제거. 기존 Board가 점유·색상 정보를 함께 비운다.
- `Tetromino` / `ItemAttachment`: 아이템 객체와 현재 모양 기준의 상대 좌표를 유지. 회전과 회전 취소에서 좌표를 함께 변환한다.
- `ItemAssigner` / `RandomItemAssigner`: 블록 생성과 별도로 아이템·실제 점유 칸을 선택한다. 테스트에서는 주입 가능하다.
- `GameEngine`: 고정 → ITEM_EFFECT(미리보기 보존) → 현재 블록 효과 1회 → 완성 행 검사 → 기존 줄 삭제 → 다음 블록 승격 / 새 NEXT 지급 순서를 관리한다.
- `GameSnapshot`: 연출 대상 `CellPosition` 목록과 강조 여부를 읽기 전용 값으로 전달한다. 화면에서 보드를 수정하지 않는다.
- `PieceSnapshot.ItemMarker`: 효과 객체를 화면에 노출하지 않고 문자·설명·좌표 값만 복사한다.
- `GameView`: 스냅샷으로 NEXT·현재 칸의 문자와 설명을 그린다. 게임 규칙·점수를 계산하지 않는다.

현재 등록된 지급 아이템은 **작은 폭탄 1종**이므로 지급 시 E가 등장한다.
이는 작은 폭탄 기능의 작업 범위이며, 과제의 전체 필수 아이템 5종 완성을 의미하지 않는다.
추가 즉시 발동형 부착 아이템은 `GameItem`을 구현하고 엔진의 기본 등록 목록에 추가하면 된다.
서로 다른 아이템은 서로 다른 문자를 사용해야 하며, 목록의 중복 문자를 거부한다.
특수 모양(무게추 등)이나 지속형 벌칙은 별도의 생명주기 설계가 필요하며 이번 인터페이스로 모두 처리된다고 가정하지 않는다.

## 검증 및 평가팀 재현 방법

```powershell
# 일반 로직 테스트 (GUI 불필요)
.\gradlew.bat :app:test

# JavaFX 실제 화면 테스트 + 전체 main 코드 커버리지
.\gradlew.bat :app:test :app:uiTest :app:jacocoTestReport

# 수동 실행
.\gradlew.bat :app:run
```

수동으로는 게임 시작 → 아이템 모드 → 난이도 선택 → 누적 10줄 삭제 후
**새 NEXT**의 E를 확인하고, 해당 블록을 원하는 곳에 고정한다.
평가 편의를 위한 강제 아이템 키나 일반 모드의 생성 확률 변경은 추가하지 않았다.

자동 테스트는 실제 엔진의 10줄 경계를 재현해 아이템을 지급하며,
테스트 전용 블록 배치로 9→10 / 9→13 / 19→21을 검증한다.
게임의 난이도별 블록 생성 알고리즘은 변경하지 않는다.

주요 검증:
- 3×3 및 네 모서리·네 변의 범위 제한, 빈 보드, 삭제 칸 색상 정보 정리
- 범위 밖 칸과 떠 있는 블록 보존, 폭발 후 완성 행만 애니메이션·채점
- 모든 7종 블록의 각 점유 칸에서 4회 회전, 역회전, 회전 실패 복원
- 실제 고정 위치의 폭발 중심, 중복·연쇄 발동 방지, 일시정지·게임 오버
- 일반 모드 아이템 금지, 새 게임 초기화, NEXT 승격 전후 동일한 아이템 유지
- JavaFX의 NEXT·현재 칸 문자 및 일반/색맹 화면과 실제 키 입력 후 폭발
- 삭제 전 보존·299→300ms 경계·두 번 깜빡임·입력 차단·일시정지·효과 후 낙하 시간 초기화
- JavaFX 실제 캔버스에서 연출 대상 칸의 밝고 어두운 픽셀 비교 및 범위 밖 픽셀 보존

화면 검증 PNG는 `app/build/ui-smoke/small-bomb-*.png`에 생성된다.
커버리지 HTML은 `app/build/reports/jacoco/test/html/index.html`, XML은
`app/build/reports/jacoco/test/jacocoTestReport.xml`에 생성된다.
보고서는 전체 main 코드를 분모로 하며 GUI 등 미검증 코드를 제외하지 않는다.
