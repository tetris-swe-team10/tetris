## 📋 구현해야 하는 요구사항

### ⚔️ 같은 PC 대전 — 혜원

- [ ]  V-1 시작 메뉴에서 대전 선택 → 일반 / 아이템 / 시간제한
- [ ]  V-2 한 PC에서 2명이 각자 진행, 두 보드 모두 표시
- [ ]  V-3 2줄 이상 삭제 시, 삭제 줄에서 마지막 블록 칸을 뺀 모양을 상대에게 전송
- [ ]  V-4 받은 줄은 대기 영역에 표시 → 상대의 다음 블록 생성 전에 보드 아래에 추가
- [ ]  V-5 추가된 줄은 회색 표시
- [ ]  V-6 대기 줄 최대 10줄 (새 공격은 아래에 추가 / 10줄이면 무시 / 넘치면 아래쪽 절단)
- [ ]  V-7 한쪽이 못 쌓으면 종료, 승자 표시
- [ ]  V-8 대전 결과는 스코어보드에 기록하지 않음
- [ ]  V-9 아이템 대전 = 일반 대전 + 아이템
- [ ]  V-10 시간제한: 타이머 만료 시 점수 높은 쪽 승리

### 🌐 P2P 대전 — 대기실까지 수연 / 게임 중 서현

- [ ]  P-1 시작 메뉴에서 P2P 선택 → 서버 / 클라이언트 (수연)
- [ ]  P-2 서버는 IP 표시 후 대기, 클라이언트는 IP 입력해 접속 (수연)
- [ ]  P-3 연결 완료 알림 → 대기 상태, 서버만 모드 선택 (수연)
- [ ]  P-4 양쪽 모두 '게임 시작'을 눌러야 시작 (수연)
- [ ]  P-5 내/상대 화면 실시간 표시, LAN 기준 지연 200ms 이하 (서현)
- [ ]  P-6 종료 후 승패 표시 → 대기 상태로 복귀, 재경기 가능 (서현 → 수연)
- [ ]  P-7 랙 표시, 오래 끊기면 에러 후 P2P 첫 화면 복귀 (감지 수연 / 게임 중 표시 서현)
- [ ]  P-8 최근 접속 IP 저장 및 선택 (수연)
- [ ]  P-9 접속 진행 메시지 표시 (수연)
- [ ]  P-10 접속 과정 자동화 테스트 (수연, 게임 중 송수신 테스트는 서현)

### 📊 평가 대비

- [ ]  N-1 기말 Line Coverage 70% (각자 테스트 작성, 수연이 측정·부족 영역 공유)
- [ ]  N-2 코드 리뷰 · 리팩토링 · 버전관리 이력
- [ ]  N-3 2차 아이템(E/B/K/L/W) 요구사항 명세서 (혜원)
- [ ]  N-4 1·2차 요구사항 재점검, 평가장 네트워크 저하 대비 (서현)

## ✅ 역할별 할 일

- [ ]  줄 삭제 시 공격 줄 생성 (마지막 블록 칸은 빈칸) → `AttackListener` 호출

- [ ]  다음 블록 생성 전 보드 아래 삽입, 넘치면 게임 오버
- [ ]  회색 칸 (`GameSnapshot.garbageCells`, `pendingAttack` 채우기)
- [ ]  `VersusMatch` 구현: 엔진 2개, 공격 전달, 승패, 시간제한 · 동점
- [ ]  엔진 단위 테스트 (2줄 미만 무공격, 10줄 경계 3종, 삽입 시점, 승패, 시간제한)
- [ ]  수연의 리팩토링 PR 리뷰

**2주차: 같은 PC 대전 화면**

- [ ]  서현의 디자인대로 대전 화면 (두 보드 · 받은 줄 영역 · 타이머), `BoardRenderer` 사용
- [ ]  2인 키 입력, 키 설정 (변경 · 저장 · 충돌 검사)
- [ ]  승자 화면 (기록 없음), 재시작 / 메인 메뉴
- [ ]  아이템 대전 규칙 반영
- [ ]  대전 화면 · 키 설정 테스트
- [ ]  2차 아이템 요구사항 명세서

### 🅱️ 수연 — 리팩토링 → P2P 대기실까지

**1주차: 커버리지 측정 + 리팩토링**

- [ ]  1주차 시작에 현재 Line Coverage 측정 → 결과와 부족한 패키지 공유
- [ ]  `GameView`에서 그리기를 분리해 `BoardRenderer` 구현
- [ ]  게임 루프 · 입력 분리, 씬 단위 키 입력을 플레이어별로 전달
- [ ]  기존 1인 게임 동작 유지, 기존 테스트 통과, 분리한 부분 테스트
- [ ]  1주차 안에 PR 병합

**2주차: P2P 대기실까지 (네트워크 + 화면)**

- [ ]  `ConnectionChannel` 구현: `ServerSocket` / `Socket` 연결 · 해제, 송수신 스레드
- [ ]  하트비트로 랙 · 끊김 판정 (`ConnectionState`, `latencyMs`)
- [ ]  대기실 메시지 (`NetMessage`): 준비 / 모드 선택(서버만) / 게임 시작
- [ ]  P2P 메뉴, 서버/클라이언트 선택, 서버 IP 표시, 클라이언트 IP 입력
- [ ]  최근 접속 IP 저장 · 선택, 접속 진행 메시지
- [ ]  대기 화면: 양쪽 준비 표시 → `P2pGameLauncher.start` 호출로 서현에게 넘김
- [ ]  끊김 시 에러 → P2P 첫 화면 (대기실 단계)
- [ ]  localhost 연결 자동 테스트 (연결 · 준비 · 시작 · 끊김 · 재연결)
- [ ]  2주차 중간 · 마무리에 커버리지 측정 → 담당자에게 공유

### 🅲 서현 — 디자인 → P2P 게임 중

**1주차: 디자인 (전체 담당)**

- [ ]  시작 메뉴 추가 항목, 대전 모드 선택 화면
- [ ]  같은 PC 대전 화면: 두 보드 · 받은 줄 영역 · 타이머 · 승자 화면 · 회색/색맹 색상 · 2인 키 안내
- [ ]  P2P 화면: 서버/클라이언트 선택 · IP 대기 · IP 입력과 최근 IP · 대기실 · 게임 화면 · 랙 · 끊김 에러 · 복귀
- [ ]  창 / 전체 / 세로 화면 크기별 배치 기준
- [ ]  화면별 목업 + 간단한 화면 명세를 1주차 안에 공유
- [ ]  (일찍 끝나면) 가짜 `ConnectionChannel`로 게임 중 송수신 뼈대 시작

**2주차: P2P 게임 중 (네트워크 + 화면)**

- [ ]  `P2pGameLauncher` 구현
- [ ]  게임 중 메시지 (`NetMessage`): 보드 스냅샷 / 공격 줄 / 게임 종료
- [ ]  직렬화 · 역직렬화, 받은 공격 줄을 `receiveAttack`으로 전달
- [ ]  200ms 이하를 위한 전송 최적화 (보내는 양 · 빈도)
- [ ]  P2P 게임 화면: 내 보드는 로컬 엔진, 상대 보드는 받은 스냅샷 (`BoardRenderer`)
- [ ]  게임 중 랙 표시, 끊김 시 에러 → `returnToP2pStart`
- [ ]  승패 표시 후 `returnToLobby`, 재경기 가능
- [ ]  게임 중 송수신 자동 테스트, 두 PC 실측 (200ms)
- [ ]  1·2차 요구사항 재점검
