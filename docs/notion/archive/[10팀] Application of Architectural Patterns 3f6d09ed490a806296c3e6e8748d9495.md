# 법인차량 관리시스템 X 아키텍처 설계

![image.png](%5B10%ED%8C%80%5D%20Application%20of%20Architectural%20Patterns/image.png)

### 설계 방향

시스템 X는 웹·앱 접속, 사진 처리, 데이터 비교, 보안, 결과 활용이라는 서로 다른 요구를 가지므로 **Client–Server를 전체 접속 구조로, Layered를 서버 내부의 기본 구조로 사용하고, 처리 기능별로 Pipe and Filter, Repository, MVC를 조합한다.**

특히 **직원만 접근할 수 있는 분석 소프트웨어·상세 데이터와 일반 이용자에게 제공할 결과를 구분**하여, 보안과 활용 기능의 확장을 함께 지원한다.

### ① Client–Server → 요구사항 1, 2

웹 브라우저와 전용 모바일 앱을 클라이언트로 두고, 서버의 동일한 운행일지 서비스를 호출하도록 하여 두 플랫폼에서 운행일지를 작성할 수 있게 한다. 신고 서비스는 전용 앱의 인증된 요청만 서버에서 허용하고 웹의 신고 요청은 거부하여, 신고 기능을 전용 앱으로 제한한다.

### ② Pipe and Filter → 요구사항 3, 4

신고 사진을 **메타데이터 추출 → 번호판·배경·사물 식별 → 차량별 시간·장소 정보 구성 → 분석 결과 저장**의 필터로 연결하고, 저장된 결과와 운행일지를 대조하는 비교 필터로 이어지도록 한다. 각 필터가 입력을 받아 다음 단계에서 사용할 출력으로 변환하므로 사진 처리와 비교 과정을 단계별로 구성할 수 있고, 분석 기술이 변경되면 해당 필터를 교체할 수 있다.

### ③ Repository → 요구사항 3, 4, 6

운행일지, 신고 사진에서 추출한 정보, 차량별 시간·장소, 비교 결과를 중앙 저장소에서 관리하여 사진 분석·운행일지 비교·결과 활용 서브시스템이 같은 데이터를 공유하도록 한다. 비교 분석은 차량 식별 정보를 기준으로 시간·장소를 운행일지와 대조하고, 활용 서비스는 권한에 따라 제공 가능한 결과만 읽도록 하여 데이터 공유와 접근 제한을 함께 유지한다.

### ④ Layered → 요구사항 5

서버를 **요청 처리 계층 → 인증·권한 검사 계층 → 업무·분석 계층 → 데이터 접근 계층**으로 구성하고, 보호 대상 분석 소프트웨어와 상세 데이터는 외부 클라이언트가 직접 접근할 수 없는 내부에 배치한다. 보호된 분석 기능에 대한 요청은 허가된 컴퓨터인지와 담당 직원의 이용 권한을 모두 확인한 뒤에만 전달하며, 일반 이용자의 결과 조회 경로에서는 해당 기능과 상세 데이터에 접근하지 못하도록 한다.

### ⑤ MVC → 요구사항 1, 6

운행일지와 분석 결과 및 관련 업무 규칙을 **Model**, 신고자·피신고자·담당 직원의 화면을 **View**, 이용자의 요청을 받아 Model의 기능을 호출하고 표시할 결과를 선택하는 부분을 **Controller**로 분리한다. 기존 결과를 이용하는 보상금 조회·위반 내역·직원용 통계 화면은 Model을 재사용하여 추가하고, 새로운 업무 처리가 필요한 경우에는 해당 Controller와 Model을 확장하여 기존 분석 과정과 화면에 미치는 영향을 줄인다.

### 전체 처리 흐름

```
웹·전용 앱
  → 운행일지 작성 서비스
  → 운행일지 저장

전용 앱의 인증된 신고 요청
  → 사진 접수
  → 메타데이터·이미지 분석
  → 차량별 시간·장소 정보 저장

허가된 컴퓨터 + 권한 있는 담당 직원
  → 보호된 비교 분석
  → 운행일지와 대조
  → 판정 결과 저장

신고자·피신고자·담당 직원
  → 이용자별 Controller와 View
  → 권한에 맞는 결과 활용
```

위반 판정이 확정되면 업무 서비스가 과제에서 제시한 기준에 따라 **차량 가격의 20배를 과태료로 계산하고, 부과된 과태료의 10%를 신고자 보상금으로 계산**한다.

### 요구사항별 대응

| 요구사항 | 적용 패턴 | 충족 방식 |
| --- | --- | --- |
| 1. 웹·앱에서 운행일지 작성 | Client–Server, MVC | 두 클라이언트가 동일한 서버 기능과 Model을 이용 |
| 2. 전용 앱에서만 신고 | Client–Server | 서버에서 신고 서비스의 접근 경로를 제한 |
| 3. 사진 분석 및 DB 저장 | Pipe and Filter, Repository | 단계별 정보 추출·변환 후 중앙 저장소에 저장 |
| 4. 차량의 시간·장소와 운행일지 비교 | Pipe and Filter, Repository | 공유 데이터를 읽어 차량별로 대조하고 결과 저장 |
| 5. 분석 소프트웨어·데이터 보호 | Layered | 내부 배치와 단말·직원 권한 검사로 접근 제한 |
| 6. 이용자별 활용 방식 추가 | MVC, Repository | 저장된 결과를 재사용하며 화면과 업무 기능 확장 |
