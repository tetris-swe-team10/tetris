## 지도에서 중간 장소 정하기 서비스

### 1. User Story

**US1.** 사용자로서 친구들의 출발 위치를 입력하면 모두의 이동 시간을 고려한 중간 지점을 추천받고 싶다. 각자의 출발 위치와 이동 시간을 따로 확인하는 불편을 줄이기 위해서다.

**US2.** 사용자로서 추천 지점 주변의 음식점과 카페를 함께 보고 싶다. 장소를 정한 뒤 다시 검색하는 수고를 줄이기 위해서다.

### 2. Scenario

**Scenario 1 (US1).** 사용자가 친구 3명의 출발 위치를 입력하고 추천을 요청한다. 시스템이 각자의 대중교통 이동 시간을 계산한다. 가장 오래 걸리는 사람의 시간이 짧은 지점을 중간 지점으로 추천한다. 참석자별 이동 시간을 지도에 표시한다.

**Scenario 2 (US2).** 사용자가 추천 지점의 주변 보기를 선택한다. 시스템이 해당 지역의 음식점과 카페를 구분해 보여 준다. 목록과 지도에 함께 표시한다.

### 3. Task

- 프로젝트 세팅, 기본 지도 화면 (T1, 6h)
- 출발 위치 입력 화면 (T2, 8h)
- 대중교통 이동 시간 API 연동 (T3, 8h)
- 중간 지점 선정 로직, 단위 테스트 (T4, 8h)
- 추천 요청·결과 화면 (T5, 10h)
- 음식점·카페 검색 API 연동 (T6, 8h)
- 음식점·카페 목록, 지도 표시 (T7, 8h)
- 예외 처리: 입력 누락, 검색 결과 없음, 조회 실패 (T8, 8h)
- 통합 시나리오 테스트 (T9, 8h)

### 4. Iteration Planning

**Iteration 1 (2주, 40h)**

- 목표: 위치를 입력하면 중간 지점이 추천된다.
- 포함: 프로젝트 세팅(T1), 출발 위치 입력 화면(T2), 이동 시간 API 연동(T3), 중간 지점 선정 로직(T4), 추천 결과 화면(T5)
- 이동 시간 API 연동(T3)이 끝나야 중간 지점 선정 로직(T4)을 만들 수 있다.
- 출발 위치 입력 화면(T2)과 중간 지점 선정 로직(T4)이 끝나야 추천 결과 화면(T5)을 만들 수 있다.
- 위험이 큰 이동 시간 API 연동(T3)은 첫날 시작한다.

**Iteration 2 (2주, 32h)**

- 목표: 주변 음식점·카페를 확인하고 예외를 처리한다.
- 포함: 음식점·카페 검색 API 연동(T6), 음식점·카페 목록 표시(T7), 예외 처리(T8), 통합 시나리오 테스트(T9)
- 주변 장소 표시(T6, T7)는 추천 지점이 있어야 가능하다.
- 예외 처리(T8)는 정상 흐름이 동작한 뒤에 붙인다.
- 분량을 적게 잡아 지연에 대비한다.

### 5. 첫 번째 Sprint (Iteration 1)

**목표:** 친구 3명의 위치를 입력하면 중간 지점이 지도에 표시된다.

- **A (14h):** 프로젝트 세팅(T1)을 먼저 끝낸다. 이후 중간 지점 선정 로직(T4)을 테스트 우선으로 구현한다.
- **B (8h):** 출발 위치 입력 화면(T2)을 맡는다. 이후 D와 추천 결과 화면(T5)을 짝 프로그래밍한다.
- **C (8h):** 이동 시간 API 연동(T3)을 첫날 시작한다. 응답 형식을 A에게 먼저 공유한다.
- **D (10h):** 추천 결과 화면(T5)을 맡는다. 1주차에는 목 데이터로 화면 틀을 만든다.

매일 짧은 스크럼으로 진행 상황을 공유한다. 스프린트 종료 시 실제 위치 4곳으로 시연한다.
