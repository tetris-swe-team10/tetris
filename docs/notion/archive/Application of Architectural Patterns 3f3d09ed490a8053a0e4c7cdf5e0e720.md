# 법인차량 관리시스템 X 아키텍처 설계

시스템 X는 운행일지 기록, 시민 신고 사진 분석, 위반 판정 및 과태료·보상금 처리라는 성격이 다른 기능으로 이루어져 있으므로, 범위별로 적합한 패턴을 조합하여 설계함.

---

**① Client-Server → 요구사항 1, 2**

서버에 핵심 로직을 두고 다수의 클라이언트를 네트워크로 연결하는 구조로, 클라이언트를 쉽게 추가할 수 있음. 운행일지는 웹과 앱에서, 신고는 전국의 시민이 앱으로 접속하므로, 웹 브라우저와 전용 앱을 각각 클라이언트로 연결하고 신고 기능은 전용 앱에만 제공하여 요구사항 1, 2를 충족함.

**② Pipe and Filter → 요구사항 3**

필터들을 파이프로 순차 연결해 데이터를 변환하는 구조로, 사람 개입 없는 순차 처리에 적합하고 필터 교체가 쉬움. 신고 사진을 업로드 → 메타데이터 추출 → 이미지 분석 → DB 저장 순으로 연결하여 요구사항 3을 충족하며, 분석 기술이 개선되면 해당 필터만 교체하면 됨.

**③ Repository → 요구사항 3, 4**

공유 데이터를 중앙 저장소에 두고 여러 서브시스템이 함께 쓰는 구조로, 대량 데이터를 동기화 없이 일관되게 공유할 수 있음. 사진 분석 결과와 운행일지를 중앙 DB에 저장하고 분석 서브시스템이 이를 공유하여 차량별 위치·시간을 운행일지와 비교함으로써 요구사항 3, 4를 충족함.

**④ Layered → 요구사항 5**

인접 레이어끼리만 통신하는 구조로, 핵심 자산을 내부 레이어에 두어 보안을 확보할 수 있음. 위치 이력과 과태료 부과 근거가 되는 분석 데이터를 가장 안쪽 레이어에 두고 바깥에 허가된 컴퓨터·직원 권한을 확인하는 인증 레이어를 두어 요구사항 5를 충족함.

**⑤ MVC → 요구사항 6**

Model, View, Controller를 분리하는 구조로, Model 수정 없이 View를 쉽게 추가할 수 있음. 분석 결과를 Model로 두고 신고자(보상금), 피신고자(위반 내역), 담당 직원(과태료 부과)별 View를 구성하여, 새 활용 방식이 필요할 때 View만 추가하면 되므로 요구사항 6을 충족함.
