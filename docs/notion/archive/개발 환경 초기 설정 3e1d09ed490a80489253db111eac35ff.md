# 개발 환경 초기 설정

생성자: 정혜원
우선순위: 높음
상태: 완료

## 1. 팀 공통 개발 환경

- **Language**: Java
- **Target Java Version**: 21
- **Build Tool**: Gradle 9.2.0
- **Gradle DSL**: Groovy
- **Test Framework**: JUnit 5
- **GUI Framework**: JavaFX 21
- **IDE**: VS Code
- **Version Control**: Git / GitHub

과제 요구사항이 Java 21 이상이므로 프로젝트 기준 버전은 Java 21로 설정하였다.

---

## 2. Gradle 프로젝트 생성

Gradle 프로젝트는 다음 설정으로 생성하였다.

```
DSL: Groovy
Project Type: Java Application
Java Version: 21
Application Structure: Single application project
Test Framework: JUnit Jupiter
New Gradle APIs: No
```

프로젝트 구조는 다음과 같다.

```
tetris/
├─ app/
│  ├─ src/
│  │  ├─ main/
│  │  │  └─ java/
│  │  └─ test/
│  │     └─ java/
│  └─ build.gradle
│
├─ gradle/
├─ gradlew
├─ gradlew.bat
└─ settings.gradle
```

Gradle Wrapper를 포함하여 별도의 Gradle 설치 없이 동일한 Gradle 버전으로 프로젝트를 실행할 수 있도록 구성하였다.

---

## 3. JavaFX 설정

`app/build.gradle`의 `plugins`에 JavaFX 플러그인을 추가하였다.

```
plugins {
    id 'application'
    id 'org.openjfx.javafxplugin' version '0.1.0'
}
```

JavaFX 21과 `javafx.controls` 모듈을 사용하도록 설정하였다.

```
javafx {
    version = '21'
    modules = ['javafx.controls']
}
```

Java Toolchain은 Java 21을 사용한다.

```
java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(21)
    }
}
```

## 5. 빌드 및 테스트

프로젝트 테스트:

```
.\gradlew.battest
```

정상적인 경우:

```
BUILD SUCCESSFUL
```

이 출력된다.

애플리케이션 기본 실행 명령어:

```
.\gradlew.batrun
```

## 6. 초기 테스트 코드 정리

Gradle 프로젝트 생성 시 자동으로 다음 샘플 테스트가 생성되었다.

```
AppTest.java
```

해당 테스트는 기존 `Hello World` 코드의 `getGreeting()` 메서드를 검사하는 샘플 테스트였으나, JavaFX 기반 `App.java`로 변경하면서 더 이상 사용하지 않기 때문에 삭제하였다.

향후 실제 게임 로직에 대해 다음과 같은 테스트를 작성할 예정이다.

```
BoardTest
TetrominoTest
CollisionTest
LineClearTest
...
```

## 7. Git 관리

초기 Gradle 프로젝트 생성:

```
chore: initialize Gradle Java project
```

JavaFX 공통 환경 설정:

```
chore: configure JavaFX project
```

현재 `main` 브랜치에는 공통 개발 환경만 반영하였다.

```
Java 21
Gradle 9.2.0
JUnit 5
JavaFX 21
Gradle Wrapper
JavaFX 기본 실행 코드
```

개인 IDE 설정인 `.vscode/`는 Git에 포함하지 않았다.

# 개인 개발 환경 이슈

아래 내용은 **팀 공통 설정이 아니라 현재 개발 PC에서 발생한 문제와 해결 방법**이다.

## 1. Gradle Worker 실행 오류

초기 테스트 과정에서 다음 오류가 발생하였다.

```
ClassNotFoundException:
worker.org.gradle.process.internal.worker.GradleWorkerMain
```

프로젝트를 한글이 없는 경로로 이동해도 동일한 오류가 발생했으며, Gradle 캐시 경로를 변경한 뒤 정상적으로 동작하였다.

Windows 사용자 환경 변수:

```
변수 이름: GRADLE_USER_HOME
변수 값: C:\GradleHome
```

설정 후:

```
.\gradlew.battest
```

실행 시 정상적으로 `BUILD SUCCESSFUL`이 출력되었다.

> 해당 설정은 개인 PC의 Gradle 실행 환경 문제 해결을 위한 것으로 GitHub 프로젝트 설정에는 포함하지 않는다.
> 

---

## 2. JavaFX 실행 시 Configuration Cache 오류

현재 개발 환경에서 기본 실행 명령어:

```
.\gradlew.batrun
```

사용 시 Gradle Configuration Cache 관련 오류가 발생하였다.

임시 실행 방법:

```
.\gradlew.batrun--no-configuration-cache
```

해당 명령어 사용 시 JavaFX 애플리케이션이 정상 실행되는 것을 확인하였다.

> 현재 개인 개발 환경에서 확인된 문제이므로 `configuration-cache=false` 등의 설정을 프로젝트 공통 파일에는 추가하지 않았다.
>

# 이후 개발 방식

공통 환경 설정 완료 후부터는 `main`에서 직접 기능을 구현하지 않고 기능별 브랜치에서 개발한다.

예시:

```
main
├─ feature/board
├─ feature/tetromino
├─ feature/movement
├─ feature/rotation
└─ feature/line-clear
```

개발 흐름:

```
Issue 생성
→ Feature Branch 생성
→ 기능 구현
→ Test 작성
→ Commit
→ Pull Request
→ Review
→ Main Merge
```

커밋 메시지 예시:

```
feat: 새로운 기능 구현
fix: 버그 수정
test: 테스트 코드 추가
docs: 문서 수정
chore: 프로젝트 환경 설정
```
