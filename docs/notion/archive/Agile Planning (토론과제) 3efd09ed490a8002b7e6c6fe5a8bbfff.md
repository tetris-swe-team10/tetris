# 실시간 맞춤 경로 안내 서비스 (네이버 지도 개선)

### **User Story 1: 경로 저장 및 실시간 경로 동기화**

지도 앱에 들어갈 때마다 출발지·목적지를 새로 검색해야 하고, 이동 중에는 처음 검색한 위치·시간 기준 경로만 볼 수 있어 불편함. 따라서 자주 가는 경로를 저장해 바로 확인하고, 이동 중에는 현재 위치·시간에 맞춰 경로가 자동 갱신되었으면 함.

### **Scenario 1: 저장된 경로로 출발 후 현재 위치 기준으로 경로 갱신**

사용자가 저장해 둔 "집 → 학교" 경로를 선택함. 이동 중 버스를 놓치자, 시스템은 목적지는 유지한 채 현재 위치·시간 기준으로 경로를 다시 계산하고 다음 버스 도착 시간과 변경된 예상 도착 시간을 표시함.

### Task

- 프로젝트 세팅, 기본 지도 화면 (T1, 4h)
- 경로 저장·삭제 기능 (T2, 6h)
- 저장 경로 목록 화면 (T3, 6h)
- 대중교통 경로 탐색 API 연동 (T4, 8h)
- 경로 안내 화면 (T5, 8h)
- 현재 위치(GPS) 추적 기능 (T6, 6h)
- 실시간 버스 도착 정보 API 연동 (T7, 6h)
- 버스 놓침 감지 로직, 단위 테스트 (T8, 8h)
- 현재 위치 기준 경로 재계산 및 화면 갱신 (T9, 8h)
- 예외 처리: GPS 수신 불가, 경로 없음, 조회 실패 (T10, 6h)
- 통합 시나리오 테스트 (T11, 6h)

### Iteration 1 (2주, 38h)

- **목표:** 저장된 경로를 선택하면 경로가 안내되고, 현재 위치가 지도에 표시된다.
- **포함:** 프로젝트 세팅(T1), 경로 저장·삭제(T2), 저장 경로 목록 화면(T3), 경로 탐색 API 연동(T4), 경로 안내 화면(T5), 현재 위치 추적(T6)
- 경로 저장·삭제(T2)가 끝나야 저장 경로 목록 화면(T3)을 만들 수 있다.
- 저장 경로 목록 화면(T3)과 경로 탐색 API 연동(T4)이 끝나야 경로 안내 화면(T5)을 만들 수 있다.
- 현재 위치 추적(T6)은 다른 작업과 독립적이지만 Iteration 2의 핵심 기능에 필요하므로 미리 진행한다.
- 위험이 큰 경로 탐색 API 연동(T4)은 첫날 시작한다.

### Iteration 2 (2주, 34h)

- **목표:** 이동 중 버스를 놓치면 현재 위치·시간 기준으로 경로가 자동 갱신된다.
- **포함:** 실시간 버스 도착 정보 연동(T7), 버스 놓침 감지(T8), 경로 재계산 및 화면 갱신(T9), 예외 처리(T10), 통합 시나리오 테스트(T11)
- 버스 놓침 감지(T8)는 경로 안내(T5), 현재 위치(T6), 실시간 버스 정보(T7)가 모두 있어야 가능하다.
- 경로 재계산(T9)은 버스 놓침 감지(T8)가 끝나야 만들 수 있다.
- 예외 처리(T10)는 정상 흐름이 동작한 뒤에 붙인다.
- 분량을 적게 잡아 지연에 대비한다.

### 첫 번째 Sprint (Iteration 1)

**목표:** 앱을 열면 저장된 "집 → 학교" 경로를 선택해 경로 안내를 볼 수 있고, 현재 위치가 지도에 표시된다.

- **A (10h):** 프로젝트 세팅(T1)을 먼저 끝낸다. 이후 경로 저장·삭제 기능(T2)을 구현하고, 팀원들의 코드 리뷰를 맡는다.
- **B (14h):** 경로 탐색 API 연동(T4)을 첫날 시작하고, 응답 형식을 C에게 먼저 공유한다. 이후 현재 위치 추적 기능(T6)을 맡는다.
- **C (14h):** 저장 경로 목록 화면(T3)과 경로 안내 화면(T5)을 맡는다. 1주차에는 목 데이터로 화면 틀을 만들고, 2주차에 A와 B의 기능을 연결한다.

매일 짧은 스크럼으로 진행 상황을 공유한다. 스프린트 종료 시 실제 통학 경로를 저장하고 선택해 경로 안내 화면을 시연한다.
