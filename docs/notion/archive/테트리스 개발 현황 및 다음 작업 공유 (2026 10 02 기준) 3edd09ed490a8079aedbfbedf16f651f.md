# 테트리스 개발 현황 및 다음 작업 공유 (2026.10.02 기준)

생성자: 정혜원
우선순위: 높음
카테고리: 분석
상태: 진행 중

게임 오버(#15), 시작 메뉴(#16), 게임 플레이(#17) PR을 모두 `main`에 머지했습니다. 머지 중 발생한 화면 연결 충돌과 테스트 중복도 정리했습니다.

현재 **시작 메뉴 → 게임 플레이 → 결과 화면 → 재시작 또는 시작 메뉴 복귀** 흐름이 연결되어 있습니다. 다음 단계에서는 점수 계산, 설정 화면, 스코어보드 진입, 블록 색상 구분을 완성해야 합니다.

## 1. 화면별 개발 현황

| 화면 | 구현된 내용 | 남은 작업 |
| --- | --- | --- |
| 시작 | 게임 시작 / 설정 / 스코어보드 / 게임 종료 메뉴 구성. 방향키·W/S로 이동, Enter로 선택. 게임 시작과 프로그램 종료 연결 | 설정·스코어보드 메뉴 연결. 현재 두 메뉴는 비활성 상태 |
| 게임 | 10×20 보드, 블록 이동·회전·자동 낙하·하드 드롭, 충돌 판정·줄 삭제·다음 블록 표시. 일시정지·재개, 게임 오버 감지 | 점수 계산과 표시 연동, 블록 종류별 색상, 설정 화면 진입 연결 |
| 설정 | 게임 화면에 설정 버튼과 화면 연결용 메서드 마련 | 설정 화면 구현, 낙하 속도·조작 키·색맹 모드 변경 및 적용, 이전 화면 복귀 |
| 스코어보드 | 기록 저장·조회 로직, 최고 점수와 상위 기록 표시 화면, 돌아가기 버튼 마련 | 시작 메뉴에서 진입하고 시작 화면으로 돌아가는 동작 연결 |
| 결과 | 최종 점수·지운 줄·최고 점수 표시, 순위 진입 시 이름 입력·기록 저장·순위 표시. 재시작 / 시작 화면 / 종료 연결 | 실제 계산된 점수 연동, 저장·조회와 화면 배치 통합 확인 |

※ 코드 구현과 연결 상태를 기준으로 정리했습니다. 전체 기능의 실행 검증은 별도로 진행해야 합니다.

## 2. 기존 논의 사항 업데이트

### 브랜치 운영 — 초기 통합 완료, 앞으로의 방식 합의 필요

이전에 논의한 “`main`이 비어 있어 다른 기능 브랜치에서 개발을 시작해야 하는 문제”는 이번 통합으로 정리되었습니다. 공통 개발 코드와 환경 수정이 `main`에 반영된 상태입니다.

앞으로는 **최신 `main`에서 작업 브랜치를 생성하고, PR로 다시 `main`에 합치는 방식**을 제안합니다.

```
git switch main
git pull --ff-only origin main
git switch -c feature/작업명
```

PR을 머지하기 전에는 최신 `main`과의 충돌을 해결하고 테스트를 확인합니다. `develop` 브랜치를 별도로 둘지는 팀에서 합의하되, 우선 브랜치 생성 기준을 통일하면 좋겠습니다.

### 점수 계산 — 담당자와 규칙 결정 필요

점수를 표시하고 결과 화면으로 전달하는 구조는 있지만, 현재 게임 진행에 따라 점수를 계산하고 갱신하는 연결이 없습니다. 따라서 게임 화면과 결과 화면의 점수가 계속 0으로 표시됩니다.

다음 내용을 정하고 구현해야 합니다.

- 줄 삭제, 소프트 드롭, 하드 드롭의 점수 규칙
- 속도 또는 레벨에 따른 점수 배율 여부
- 점수 계산 담당 위치와 담당자
- 게임 화면 → 결과 화면 → 저장 기록에 동일한 점수가 전달되는지 확인

`GameView.setScore()`는 연결 지점으로 마련되어 있습니다.

### 블록 종류 저장·색상 구분 — 개발 필요

현재 `Board.lock()`은 고정된 블록을 모두 `1`로 저장하므로 종류 정보가 사라집니다. 렌더링에서도 블록 종류별 색상을 사용하지 않아, 현재 블록·다음 블록·쌓인 블록을 종류별로 구분할 수 없습니다.

**보드에 블록 종류를 보존하고, 해당 종류에 따라 색상을 그리는 작업**이 필요합니다.

기존 제안인 `TetrominoType[][]` 사용을 검토하되, `getCell()`뿐 아니라 `setCell()`, 충돌 판정, 줄 삭제, 기존 테스트까지 함께 점검해야 합니다. 핵심 자료구조 변경이므로 관련 담당자끼리 인터페이스를 먼저 합의하면 좋겠습니다.

### 색맹 모드 — 방식과 담당자 합의 필요

**색맹 친화 팔레트 + 문자 또는 패턴 표시**를 함께 적용하는 방향을 제안합니다. 색상만으로 구분하지 않도록 하고, 일반 모드에서도 좌우가 반전된 블록의 대비를 확보해야 합니다.

합의할 내용은 다음과 같습니다.

- 일반 모드와 색맹 모드의 블록별 팔레트
- 문자·패턴의 표시 방식과 가독성
- 현재 블록·다음 블록·고정된 블록에 동일하게 적용
- 설정 변경 시 적용 시점과 설정 유지 범위

이전에 제안한 담당자와 화요일 구현 일정은 회의에서 다시 확정하면 좋겠습니다.

### `App.java` 화면 전환 — 기본 연결 완료

시작 메뉴에서 게임을 시작하고, 게임 오버 후 재시작하거나 시작 메뉴로 돌아가는 흐름은 연결했습니다.

남은 연결은 **설정 화면과 독립 스코어보드 화면**입니다. 여러 작업에서 `App.java`를 동시에 수정할 수 있으므로, 화면 연결 부분은 담당자끼리 미리 조율하면 충돌을 줄일 수 있습니다.

## 3. 다음 개발 작업 제안

| 우선순위 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 점수 계산·연동 | 플레이 중 점수가 증가하고, 결과 화면과 저장 기록에 같은 점수가 반영됨 |
| 1 | 스코어보드 화면 연결 | 시작 메뉴에서 기록 조회 가능, 시작 화면으로 복귀 가능 |
| 1 | 설정 화면 구현·연결 | 시작 메뉴와 게임 중 진입 가능, 설정 적용 및 이전 화면 복귀 가능 |
| 2 | 블록 종류 보존·색상 구분 | 현재·다음·고정 블록 모두 종류별 표시 유지 |
| 2 | 색맹 모드 | 설정에서 전환 가능, 색상 외 구분 표시 적용 |
| 3 | 통합 검증·화면 정리 | 전체 화면 이동, 입력 포커스, 재시작 초기화, 기록 저장·조회 확인 |

현재 게임 중 **설정 버튼을 누르면 화면 전환 없이 일시정지만 되는 상태**입니다. 설정 화면 연결 전까지는 버튼을 비활성화하거나 동작을 정리할 필요가 있습니다. 현재 게임 중 일시정지·재개 키는 `Esc`입니다.
