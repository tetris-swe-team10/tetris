# P-A-002 · 리디자인 전 화면 스타일을 CSS로 모으고 요구사항 점검표를 함께 쓰기

상태: 초안·B/C 의견 수집 / 작성자: A/Claude / 받는 역할: B,C / 작성일: 2026-11-16

- 문제·목적: A가 화면을 더 보기 좋게 다시 꾸미고 싶다는 의견을 냈다. 그런데 지금은 색·글꼴·테두리가 Java 코드의 `setStyle("...")` 문자열에 흩어져 있다. 그래서 디자인을 바꾸려면 화면 클래스를 직접 고쳐야 하고, 같은 파일을 B의 렌더러 리팩토링도 고친다. 리디자인 중에 교수님 요구사항(아래 점검표)을 빠뜨릴 위험도 있다.
- 제안:
  1. **스타일을 CSS로 옮긴다.** Java의 인라인 스타일을 `styleClass`와 기존 CSS 파일(`src/main/resources/com/team10/tetris/*.css`)로 옮긴다. 공통 색은 CSS 루트 변수(예: `-color-bg`, `-color-accent`)로 한 곳에서 정의한다. 동작·레이아웃·테스트 기대값은 바꾸지 않는다.
  2. **블럭 색은 지금처럼 `BlockPalette`에 둔다.** Canvas로 그리는 보드는 CSS가 적용되지 않으므로 옮기지 않는다. 색맹 팔레트 검증 테스트(`BlockPaletteTest`)를 계속 쓴다.
  3. **리디자인 PR마다 아래 점검표를 본문에 붙인다.**
  4. **역할 경계를 지킨다.** 디자인 결정(색·배치·목업)은 C, `GameView` 그리기 분리는 B의 리팩토링 PR을 따른다. A는 CSS 이전 작업을 B 리팩토링 병합 **이후**에 하거나, B와 파일이 겹치지 않는 화면(시작 메뉴·모드 선택·종료 화면·키 설정 창)부터 한다.
- 대안:
  - CSS로 옮기지 않고 C의 목업을 바로 Java 코드에 반영한다. 이 방법은 다음 디자인 수정 때 같은 비용이 다시 든다.
  - 외부 웹 디자인(React Bits 등)을 그대로 가져온다. JavaFX CSS는 웹 CSS와 달라 그대로 적용되지 않는다. 특정 사이트 디자인을 통째로 베끼면 저작권 문제가 생길 수 있다. 참고는 분위기·색 조합 수준으로만 한다.
- 영향받는 코드·역할·호환성:
  - 인라인 `setStyle` 사용(2026-11-16, `feature/local-versus` 기준): `GameOverView` 21곳, `GameView` 9곳, `StartScreen` 4곳, `KeyBindingDialog` 3곳, `ModeSelectionScreen` 1곳.
  - B: `GameView`가 렌더러 리팩토링 대상이라 겹친다. 순서 합의가 필요하다.
  - C: 디자인 토큰(색 이름·값)을 C의 목업 기준으로 정한다.
  - 공용 인터페이스(`BoardRenderer`, `GameSnapshot` 등)는 바꾸지 않는다.
- 관련 요구사항·Issue·PR: 1차 5·7·8·9·10·12·13·15쪽, 2차 2·3·6·7·8·10쪽, 3차 2·4·5·9·10·13쪽. Issue는 의견 수렴 후 등록한다. 관련 PR: #59(같은 PC 대전 화면, 리뷰 중), #61(사용하지 않는 일시정지 버튼 제거), #63(종료 화면 문구).
