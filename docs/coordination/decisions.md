# 결정과 해석 기록

> 정리일: 2026-11-09 · 기존 합의의 재정리와 새 운영 제안을 구분 · 원문 노션은 수정하지 않음

## 기록 방법

한 항목에는 ID, 상태, 근거, 영향 범위를 적는다. 새 팀 결정을 임의로 확정하지 않는다. 결정이 바뀌면 기존 항목을 지우지 않고 대체 항목을 연결한다. 정책의 상태와 기능의 실행 검증 상태는 다르다.

| ID | 상태 | 내용 | 근거·연결 |
| --- | --- | --- | --- |
| D-001 | 기존 팀 관례 | Java 21·JavaFX 21·Gradle Wrapper·JUnit 사용 | 노션 「개발 환경 초기 설정」, `app/build.gradle` |
| D-002 | 기존 팀 관례 | 기능별 브랜치, `feat/fix/docs/refactor/test/chore` 커밋 | 노션 「개발 운영 방식」. 브랜치 이름에 `codex/`를 넣지 말라는 사용자 지시도 적용 |
| D-003 | 사용자 승인·구현 확인 | 낙하 100점, 가속 시 추가 100점, 줄당 1000점·추가 동시 삭제 줄당 500점 | 기존 대화, [점수 명세](../scoring-difficulty.md), `StandardScoringPolicy` |
| D-004 | 사용자 승인·구현 확인 | I 가중치 12/10/8, 5줄마다 80/100/120ms 감소. 기본 간격 1250/1000/750ms와 분리 | 기존 대화, [설정 명세](../settings.md), `Difficulty`, `GameEngine` |
| D-005 | 구현·후속 명세 확인 | E/B/K/L/W를 공통 지급, B는 다음 블록 수명, K는 자신에게 적용. 과거 3%·B 3초·다음 블록 K 초안은 현재 규칙이 아님 | 노션 「item 명세서」·B/K 기능 기록, 각 아이템 명세와 코드 |
| D-006 | 사용자 지시 | 일상 검증은 변경 부분과 직접 영향받는 테스트만 실행 | 기존 대화의 시간·토큰 절약 요청, [품질 관리](../quality-and-evaluation.md) |
| D-007 | 이번 요청의 정리 범위 | AI 공통 진입점과 상세 docs, 노션 출처·결정·현황을 분리 | 2026-11-09 사용자 요청. 새 역할 배정이나 교수님 미결정 사항의 확정을 포함하지 않음 |

자료를 코드와 대조해 적은 항목은 전체 기능이 현재 통과했다는 뜻이 아니다. 이번 정리에서는 게임 테스트를 실행하지 않았다.

## 새 결정 양식

```text
ID: D-다음 번호
제목:
상태: 제안 / 합의 / 확인 필요 / 대체됨
결정일·결정자:
내용·영향 범위:
근거: 사용자 답변 / 회의 / e-class / 이슈·PR URL
대체하는 항목:
필요한 구현·검증·문서 갱신:
```

원문 위치와 작성자별 자료는 [노션 목록](../notion/README.md)에서 확인한다.
