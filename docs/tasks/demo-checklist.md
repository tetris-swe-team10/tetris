# 최종 시연 체크리스트와 부족한 부분

> 작성 2026-11-18 · A/Claude · 상태: 점검표 초안. **이 문서 작성 중 게임 실행·테스트·커버리지 측정은 하지 않았다.**
> 기준: 1~3차 요구사항을 평가 항목 단위로 나눈 점검표(1-1~8-31), 우리 `origin/main` `4cccf18`.
> 항목 번호는 교수님 PDF 쪽 번호와 다른 체계다. 올해 원문과 다르면 원문을 따른다. A 대전 시연 절차는 [A 평가 시연](A-evaluation.md)을 따른다(PR #66 리뷰 중, 병합 전까지 링크는 PR 브랜치에만 있음).

## 표기

- **코드 근거**: main에 구현·테스트 파일이 있다. 실제 시연 통과는 아님.
- **부족**: main에서 구현·근거를 찾지 못했다.
- **증거 필요**: 구현과 별개로 평가 때 보여 줄 자료(측정값·링크·캡처)가 아직 없다.
- 시연 칸은 실제로 실행한 날짜·실행자·결과만 적는다.

## 부족한 부분 요약

1. **P2P 대전 전체(8-1~8-31)가 main에 없다.** 전체 항목의 약 1/5이다. B(연결·대기실)·C(P2P 게임 화면·복귀) 담당이므로 A가 대신 구현하지 않고 진행 상황을 확인한다. 8-24~8-29에는 지연 표시, 양쪽 준비 상태, 끊김 감지, 실제 연결 자동 테스트가 필요하다.
2. **2-12·2-13 전용 단위 테스트가 없다(6-7·6-8).** 키 입력 → 엔진 반영을 시간 주입으로 확인하는 작은 테스트로 보강할 수 있다.
3. **최종 Line Coverage 70% 측정이 없다(6-6).** 같은 커밋에서 `test`+`uiTest`+`jacocoTestReport`를 한 번 실행해 기록해야 한다(B 측정).
4. **최소 사양·1초 미만 지연 근거가 없다(6-4·6-5).** 메모리 제한 실행(`-Xmx`) 같은 방법을 팀이 정해야 한다.
5. **프로젝트 관리 증거가 약하다(6-16~6-19).** 노션 기록과 이슈 담당자 지정은 있지만 GitHub 마일스톤·역할 라벨이 없다. 평가 때 보여 줄 링크를 하나로 정해야 한다.
6. **리뷰 없이 병합된 PR이 있다(6-15).** 앞으로의 PR은 동료 리뷰 후 병합을 지킨다.
7. **모든 항목이 시연 미실행이다.** 최종 커밋이 정해지면 Windows 패키지를 다시 검증하고, 위 표의 시연 칸을 채운다.
