# C · 서현 · 디자인과 P2P 게임 진행

목표: 전체 화면 명세와 연결 완료 이후 P2P 게임·승패·복귀를 책임진다.
출처·공통 완료 기준: [작업 시작점](README.md).

## 1주차 · 디자인

- [ ] 시작 메뉴·모드 선택·두 보드·받은 공격·타이머·승자 화면 목업
- [ ] 회색/색맹 표시·2인 키 안내·창/전체/세로 배치 기준
- [ ] P2P 서버/클라이언트·IP·최근 IP·대기실·게임·랙·오류 화면 명세
- [ ] A/B에게 화면별 목업·전환·버튼 동작 공유
- [ ] 여유 시 가짜 `ConnectionChannel`로 게임 중 흐름 개발

## 2주차 · P-5, P-6, P-7 표시

- [ ] `P2pGameLauncher` 구현, `start` 반환 전 수신 핸들러 설치
- [ ] `BoardStateMessage`에 로컬 `GameSnapshot`을 담아 전송
- [ ] `AttackMessage` → 로컬 `GameEngine.receiveAttack`
- [ ] 로컬 엔진과 받은 상대 스냅샷을 `BoardRenderer`로 표시
- [ ] 전송량·주기 조정, LAN 두 PC에서 입력→표시 200ms 이하 실측
- [ ] 랙 표시, 게임 중 끊김 → 오류 → `returnToP2pStart`
- [ ] 승패 표시 → `returnToLobby`, 재경기
- [ ] 직렬화·수신·공격·게임 종료·화면 복귀 관련 자동 테스트
- [ ] 1·2차 요구사항·평가장 네트워크 저하 대비 점검

## 연동 경계

연결·준비·서버 모드 선택은 B, 게임 중 처리·종료 후 복귀 요청은 C다.
공격 생성·큐 제한·삽입 시점은 A 엔진을 재사용한다. 화면에서 별도 공격 규칙을 만들지 않는다.
가짜 채널 테스트와 실제 두 PC 측정은 별도 증거로 기록한다.
