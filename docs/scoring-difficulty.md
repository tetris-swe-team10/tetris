# 점수·난이도·삭제 상태 연동

구현 브랜치: `feature/scoring-difficulty`. 2026-10-09 사용자와 합의한 규칙을 구현했다. 아이템 동작은 정수연 담당이며 이 변경에 포함하지 않았다.

## 플레이와 점수

시작 메뉴에서 게임 시작을 선택하면 Easy / Normal / Hard 선택 창이 열린다. 취소하면 게임을 생성하지 않는다. 확정한 `GameConfig`는 불변이며 설정 화면이나 게임 중에는 난이도를 변경하지 않는다. 다시 시작은 같은 난이도로 새 엔진을 만들고, 시작 메뉴로 돌아가면 다시 선택할 수 있다.

- 성공한 낙하 1칸: 100점. 자동·아래 키·하드 드롭 모두 동일.
- 기본 1000ms보다 빨라진 상태의 성공한 낙하: 200점.
- 삭제한 줄: 줄당1000점.
- 자체 추가 규칙: 동시에 삭제한 추가 줄마다500점. 1/2/3/4줄은1000/2500/4000/5500점.
- 실패한 이동·회전, 착지 자체, 일시정지·삭제 연출·종료 중 입력: 낙하 점수 없음.
- 점수의 단일 원천은 `GameEngine`. 게임 화면, 결과, 기록 저장에 동일 값을 전달한다.

## 난이도

| 난이도 | I 가중치 | 나머지 각 가중치 | I 실제 확률 | 5줄마다 간격 감소 |
|---|---:|---:|---:|---:|
| Easy | 12 | 10 | 12/72 ≈16.67% | 80ms |
| Normal | 10 | 10 | 10/70 ≈14.29% | 100ms |
| Hard | 8 | 10 | 8/68 ≈11.76% | 120ms |

초기1000ms, 최소200ms. 20%는 **기존100ms 간격 감소량**을 기준으로 해석했다. 낙하 빈도의 증가율과는 다른 해석이며 사용자가 이 방식을 선택했다. I의 20%는 가중치 조정으로 구현한다. 첫 블록·NEXT·후속 생성 모두 같은 `PieceGenerator`를 사용한다.

`WeightedPieceGenerator`는 누적 가중치 Roulette Wheel Selection을 구현한다. 테스트에서는 실제 엔진의 생성 경로를 난이도마다10만 회 호출하고 각7종에 대해 기대 확률 대비 상대오차5% 이내인지 검사한다. 고정 seed로 재현하며 전체 ticket 경계도 별도로 검증한다. UI/프로덕션에서는 seed를 고정하지 않는다.

## MVC와 상태 전달

- Model: `GameEngine`, `Board`, `Tetromino`, 불변 `GameConfig`. 점수·난이도 규칙에 `ScoringPolicy`와 `PieceGenerator`를 주입한다.
- Controller: `GameController`. 입력 명령과 경과시간, 낙하 타이머를 조정한다.
- View: `GameView`. JavaFX 입력을 명령으로 바꾸고 Controller에 전달하며 `GameSnapshot`을 그린다.
- App: 생성 및 화면 연결. 결과 및 저장에 게임의 모드·난이도를 전달한다.

상태는 `PLAYING`, `CLEARING`, `PAUSED`, `GAME_OVER`다. JavaFX 타입은 도메인과 Controller에 들어가지 않는다. 기존 엔진 getter/fixture 메서드는 기존 테스트 호환용으로 남겼지만 화면 렌더링은 deep immutable snapshot을 사용한다.

착지 시 `Board.findFullRows()`로 삭제할 행을 찾는다. `CLEARING` 상태에서는 보드와 행 좌표를 유지하고, 화면에0.3초 동안 흰색 강조를 표시한다. 조작과 자동 낙하는 차단된다. 일시정지하면 연출 시간도 멈추며 재개 시 남은 시간을 진행한다. 그 뒤 `removeRows()` → 점수·누적줄·속도 갱신 → 기존 NEXT 활성화 → 새 NEXT 생성 → 생성 실패 시 종료 순서로 처리한다.

`Board.clearLines()`는 기존 테스트/호출을 위한 즉시 삭제 편의 API다. 게임 진행에서는 지연된 삭제 단계와 `removeRows()`를 사용한다. 행 목록은 압축 전 보드 좌표이며 중복은 한 번만 삭제된다.

## 기록과 호환성

상위10개 및 순위 진입 판단은 **모드·난이도별**로 독립 적용된다. 시작 메뉴 스코어보드에서 모드와 난이도를 선택할 수 있다. ITEM은 기록 분류 및 이후 팀원 연동용이며 아직 아이템 게임 시작 메뉴는 활성화하지 않았다.

TSV 새 형식:

```text
Base64(UTF-8 이름) TAB 점수 TAB 지운줄 TAB ISO시각 TAB NORMAL|ITEM TAB EASY|NORMAL|HARD
```

기존4열 기록은 일반/Normal로 읽는다. 다른 난이도 그룹을 정리해도 기존 일반/Normal 기록을 보존한다. 손상된 행은 건너뛰며 기존 파일 전체를 초기화하지 않는다. 상위 기록 정리는 임시 파일을 작성한 뒤 교체한다. 그룹 최하위와 동점이면 기존 기록을 유지한다.

기존 매개변수 없는 조회 API는 호환을 위해 전체 기록을 조회할 수 있다. 새 UI/결과에서는 반드시 mode/difficulty가 있는 API를 사용한다. 과거 게임의 메타데이터는 없으므로 일반/Normal 해석은 이전 데이터에 대한 호환 정책이지 실제 과거 난이도의 증명이 아니다.

## 팀원 연동 시 주의

1. 아이템은 모양·셀 마커·접촉 상태를 추가해야 한다. 이 변경은 아이템 엔진을 구현하지 않았다. ITEM 식별자만으로 아이템 게임이 완성되지 않는다.
2. `Board.removeRows(Collection<Integer>)`는 일반 완성행과 L 대상 행을 합친 집합을 처리하는 데 재사용 가능하다. 압축 전 좌표를 사용해야 한다.
3. 아직 Engine의 착지 경로는 `findFullRows()`만 사용한다. 아이템 담당자가 효과 및 대상 행 결정을 연결해야 한다.
4. 색맹 브랜치와 합칠 때 `removeRows()`가 `cellTypes`/마커도 함께 압축하도록 수정하고, snapshot에 타입/마커를 추가해야 한다. 기존 색맹 브랜치의 즉시 삭제 `clearLines()`만 수정해서는 새 게임 경로에 적용되지 않는다.
5. `GameView.setScore()`는 제거했다. 엔진 점수를 읽는다. 결과 화면의 `showResult(score, lines, config)`와 기록 그룹 API를 사용한다.
6. 설정 담당자는 `setOnSettingsRequested()`로 연결한다. 콜백을 연결하기 전에는 게임 화면 설정 버튼을 비활성화한다. 난이도는 해당 설정에 추가하지 않는다.

## 검증 및 실행

```powershell
.\gradlew.bat :app:test
.\gradlew.bat :app:uiTest
.\gradlew.bat :app:run
```

일반 `test`는 순수 로직·입력 매핑·기록 테스트를 실행한다. `uiTest`는 데스크톱 JavaFX가 필요하다. 실제 Scene에서 난이도 선택/취소, 점수 표시, 삭제행 표시, 결과 저장 및 기록 필터를 검사한다. UI 스냅샷은 `app/build/ui-smoke/`에 생성하며 Git에 포함하지 않는다. 각 보고서는 `app/build/reports/tests/test/`, `app/build/reports/tests/uiTest/`에 있다.

검증은 해당 변경의 기능·회귀에 관한 것이다. 프로젝트 전체 커버리지, 배포 패키지, 설정 화면 및 아이템 모드까지 완료됐다고 의미하지 않는다.
